# Користувачі сервера UAKinogo

Авторизація доступна з **0.1.0-beta.45**. Для авторизації потрібне оновлення обробника Ubuntu. Старий обробник лишається сумісним із запитами без авторизації.

## Локальне підключення без пароля

З **beta.45.1** можна окремо дозволити домашню мережу. У SSH-сесії Ubuntu:

```sh
curl -fL https://raw.githubusercontent.com/serg-ill/ukr-by-faborn/v0.1.0-beta.46/server/uakinogo/install.sh -o /tmp/faborn-install.sh &&
sudo bash /tmp/faborn-install.sh --port 8789 --allow-lan 192.168.88.0/24
```

На телевізорі перезапустіть Lampa → **ukr by Faborn → UAKinogo · сервер → Очистити логін і пароль**. Адреса вдома: `http://192.168.88.191:8789`. Порожній логін показує **Не задано**. Тестових облікових даних у розширенні немає.

Наявні користувачі й паролі залишаються чинними. З іншої мережі потрібні їхні логін / пароль або ключ. Локальний виняток використовується лише для запитів без облікових даних; неправильні явно передані дані повертають 401. Якщо ввімкнути виняток на сервері без користувачів або ключів, він не створить зовнішню авторизацію: облікові записи налаштовуються окремо.

Виняток типово вимкнений. `--allow-lan none` прибирає його; без параметра інсталятор зберігає поточну політику. Налаштування записується як `FABORN_ALLOW_LAN` у `/etc/faborn-resolver.env`. Приймається одна коректна приватна IPv4-мережа, включно з окремою адресою `/32`. Перевіряється TCP-адреса, також у формі IPv4-mapped IPv6; `X-Forwarded-For`, `X-Real-IP` та `Forwarded` ігноруються. Не використовуйте цей виняток за проксі або SNAT, який підмінює адреси зовнішніх клієнтів локальною адресою. Звичайний DST-NAT MikroTik зберігає адресу зовнішнього клієнта.

Публічний `/health` показує `localAccess: allowed` при ввімкненому винятку. Авторизація зовнішніх клієнтів відображається окремим полем `auth`. Для нового правила потрібне оновлення Ubuntu; очищення полів тільки в Lampa не змінює серверної авторизації.

## Облікові записи

Інсталятор з `--test-users` створює **test1** та **test2** з різними випадковими паролями. Після оновлення можна створити їх окремою командою в SSH-сесії Ubuntu:

```sh
sudo /opt/faborn-resolver/node/bin/node /opt/faborn-resolver/current/server/uakinogo/users.js test-users
```

Команда покаже `test1:ВИПАДКОВИЙ_ПАРОЛЬ` та `test2:ІНШИЙ_ВИПАДКОВИЙ_ПАРОЛЬ`. Збережіть ці значення приватно. Повторний запуск не змінює паролі наявних test1/test2.

На телевізорі вставте `test1:ПАРОЛЬ@192.168.88.191:ПОРТ` у **Налаштування → ukr by Faborn → UAKinogo · сервер → Сервер UAKinogo**, або задайте адресу, логін і пароль окремо. Використовуйте фактичний порт, показаний інсталятором. Пароль редагується із прихованими символами й не додається до історії клавіатури.

Для друзів з іншої мережі вказуйте адресу вже доступного ззовні обробника; `192.168.88.191` працює лише вдома. Basic через HTTP не шифрує пароль; для передавання через інтернет використовуйте HTTPS. Авторизація захищає запити метаданих, а відео надходить прямо на телевізор.

Додавання, перелік, зміна пароля й відкликання доступу:

```sh
sudo /opt/faborn-resolver/node/bin/node /opt/faborn-resolver/current/server/uakinogo/users.js add friend --generate
sudo /opt/faborn-resolver/node/bin/node /opt/faborn-resolver/current/server/uakinogo/users.js list
sudo /opt/faborn-resolver/node/bin/node /opt/faborn-resolver/current/server/uakinogo/users.js reset friend --generate
sudo /opt/faborn-resolver/node/bin/node /opt/faborn-resolver/current/server/uakinogo/users.js delete friend
```

Новий випадковий пароль друкується тільки при створенні або зміні. Для власного пароля підтримується `--password-stdin`; пароль не слід передавати в аргументах командного рядка. `--file PATH` вказує інший файл, якщо той самий шлях задано в `FABORN_USERS_FILE` у `/etc/faborn-resolver.env`.

Паролі зберігаються як хеші scrypt із випадковою сіллю в `/opt/faborn-resolver/auth/users.json`, окремо від файлів випуску. Файл має права 600, каталог — 700. Інсталятор зберігає наявні облікові записи при оновленні. Без користувачів початковий режим лишається відкритим; додавання першого вмикає Basic для запитів метаданих, крім окремо дозволеної локальної мережі.

Зміни діють з наступного запиту без перезапуску сервісу. Видалення останнього користувача лишає авторизацію увімкненою й доступ закритим. Відсутній або некоректний налаштований файл також закриває доступ. Попередні `FABORN_ACCESS_KEYS` сумісні з користувачами.

`GET /health` лишається публічним: показує `auth: basic`, `basic+key`, `key` або `none`, без логінів, паролів чи потоків. Неправильний логін / пароль дає HTTP 401. Неправильні входи входять до ліміту запитів; кількість одночасних перевірок пароля обмежена.
