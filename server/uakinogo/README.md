# UAKinogo · серверна бета 0.1.0-beta.42

Обробник для **ukr by Faborn**. Ubuntu отримує сторінки джерела та JSON плеєра й повертає телевізору озвучення, сезони, серії та посилання. **Плейлисти HLS, ініціалізаційні файли й відеосегменти через Ubuntu не проходять.** Сервер не перекодовує відео і не має маршруту медіапроксі.

**Модуль beta.42 додає клієнтську перевірку локального HLS-каналу, виправлений порядок закриття AVPlay після помилки та докладнішу діагностику. Обробники Ubuntu beta.40 / beta.41 сумісні; переустановлення не потрібне.** Повністю перезапустіть Lampa та збережіть свою адресу сервера й порт. Новий серверний пакет beta.42 має той самий API та ліміт 16 KiB. Виправлення запиту HTTP 413 з beta.41 збережене. Фізичне відтворення 4K UAKinogo після цього клієнтського оновлення ще потрібно перевірити.

У першій бета доступ без ключа. Модуль на телевізорі вимкнений за замовчуванням. Старе налаштування Alloha його не активує.

## Встановлення з Mac

Потрібні Ubuntu 22.04 або новіша, процесор x86_64 / arm64, systemd і користувач із `sudo`. У Terminal на Mac підключіться до Ubuntu (замініть `USERNAME` своїм логіном Ubuntu):

```sh
ssh USERNAME@192.168.88.191
```

У вже відкритій SSH-сесії завантажте [актуальний інсталятор beta.42](https://raw.githubusercontent.com/serg-ill/ukr-by-faborn/main/server/uakinogo/install.sh) та запустіть. Він містить виправлення конфлікту портів і встановлює серверний пакет beta.42:

```sh
curl -fL https://raw.githubusercontent.com/serg-ill/ukr-by-faborn/main/server/uakinogo/install.sh -o /tmp/faborn-install.sh
sudo bash /tmp/faborn-install.sh
```

Інсталятор перевіряє SHA-256 випуску й офіційного [Node.js 24 LTS](https://nodejs.org/en/download), встановлює окремий Node у `/opt/faborn-resolver`, створює непривілейованого користувача `faborn-resolver` та сервіс systemd із автозапуском. Системний Node та інші застосунки не замінюються. Після невдалого оновлення чинного обробника повертаються попередні файли, runtime, конфігурація порту та стан автозапуску. Установлення на вашому Ubuntu виконуєте ви; на фізичному сервері користувача виправлений інсталятор ще не перевірено.

Перед завантаженням перевіряється зайнятість порту. Типово це `8787` або порт із наявної конфігурації. Якщо його використовує інший сервіс, обирається наступний вільний порт у межах 20 наступних значень. Наприкінці скрипт друкує **фактичний порт**: використайте його в `/health` та в налаштуваннях телевізора. Для заданого порту:

```sh
sudo bash /tmp/faborn-install.sh --port 8788
```

Якщо явно заданий порт зайнятий, скрипт зупиняється до зміни обробника. Запущений Faborn може залишатися на своєму порту при оновленні; чужі сервіси не зупиняються. HTTP-перевірка також перевіряє, що порт слухає саме процес Faborn.

Перевірте з Mac або браузера в тій самій мережі:

```sh
curl http://192.168.88.191:8787/health
```

Очікувана відповідь містить `"ok":true`, `"version":"0.1.0-beta.42"`, `"auth":"none"`, `"videoProxy":false`.

## Налаштування телевізора

1. Перезавантажте Lampa; у діагностиці Faborn має бути **0.1.0-beta.42** або новіше.
2. **Налаштування → ukr by Faborn → Сервер UAKinogo**: введіть адресу свого Ubuntu, наприклад `http://192.168.88.191:8787`.
3. **UAKinogo · серверна бета → Увімкнено**.
4. У налаштуваннях плеєра Lampa оберіть **Tizen / AVPlay**. Для нового джерела ця бета використовує штатний плеєр Lampa, навіть якщо для звичайних джерел вибраний Faborn Player.
5. Відкрийте картку → іконка Faborn → якість → озвучення **UAKinogo / Alloha**. Стан недоступного джерела також видно в цьому вікні.

Звичайні джерела залишаються доступними. Для вимкнення експерименту достатньо повернути його перемикач у «Вимкнено».

## Межі першої бети

- На телевізорі потрібні **Tizen 5.5+**, доступний `tizentvwasm.SocketsManager`, Worker / WebAssembly та AVPlay. Це залежить також від збірки застосунку Lampa. Перед запуском модуль перевіряє API й показує причину відмови.
- CDN вимагає `Origin` для кожного медіазапиту. Заголовок додає адаптер **на самому телевізорі**, AVPlay читає його локальну адресу `127.0.0.1`. Ubuntu не бере участі в цій передачі.
- На 04.10.2026 HTTP-перевірка «Оппенгеймера» й «Унабомбера» підтвердила 3840×2160 **AV1 + AAC**, UA / EN / RU. «Друзі»: 234 серії, до 1080p. Наявність 4K-посилання не гарантує підтримку кодека телевізором. Фізичне відтворення на Samsung і передавання посилання між різними зовнішніми IP ще не перевірені.
- Вибір сезонів / серій, прогрес, «З початку» й перемикання озвучення доступні. **Автоперехід UAKinogo на наступну серію у першій бета ще не підключений**; наступну оберіть у меню серій. На інші джерела це обмеження не поширюється.
- Локальна адреса `192.168…` доступна тільки в домашній мережі. Для друзів в інших мережах знадобиться окрема публічна HTTPS-адреса. Інсталятор не відкриває порти маршрутизатора, не змінює firewall і не публікує домашній сервер.
- Якщо `/health` відкривається на Mac, а телевізор показує `SERVER`, можливе блокування локального HTTP збіркою Lampa; тоді потрібна HTTPS-адреса обробника. Сервер не вимикає перевірку TLS.

## Обслуговування

```sh
sudo systemctl status faborn-resolver --no-pager
sudo journalctl -u faborn-resolver -n 50 --no-pager
sudo systemctl restart faborn-resolver
```

Конфігурація: `/etc/faborn-resolver.env`. Типово `HOST=0.0.0.0`, `PORT=8787`, `FABORN_ACCESS_KEYS=`. HOST і ключі зберігаються при повторному встановленні; PORT змінюється лише за `--port` або коли наявний порт зайняв інший сервіс. Для ручної зміни порту відредагуйте його та перезапустіть сервіс; змініть адресу і на телевізорі.

### Відновлення після EADDRINUSE / 401 у старому інсталяторі beta.40

`EADDRINUSE` означає, що порт уже зайнятий. `GET /health` Faborn не вимагає ключа, тому 401 під час цього збою надходить від іншого сервісу. Після невдалого першого встановлення старий інсталятор залишає файли на місці, але вимикає Faborn. Якщо порт `8788` вільний, можна відновити встановлене без повторного завантаження:

```sh
sudo bash <<'SH'
set -euo pipefail
listeners=$(ss -H -ltn 'sport = :8788')
if [ -n "$listeners" ]; then
    echo 'Порт 8788 зайнятий. Оберіть інший вільний порт.' >&2
    exit 1
fi
test -f /etc/faborn-resolver.env
unit_source=/opt/faborn-resolver/current/server/uakinogo/faborn-resolver.service
test -f "$unit_source"
sed -i 's/^PORT=.*/PORT=8788/' /etc/faborn-resolver.env
install -m 0644 "$unit_source" /etc/systemd/system/faborn-resolver.service
systemctl daemon-reload
systemctl enable faborn-resolver.service
systemctl restart faborn-resolver.service
curl -fsS --retry 5 --retry-connrefused --retry-delay 1 --max-time 3 http://127.0.0.1:8788/health
printf '\nАдреса для телевізора: http://192.168.88.191:8788\n'
SH
```

Очікується `"ok":true`, `"auth":"none"`, `"videoProxy":false`. Адреса з Mac: `http://192.168.88.191:8788/health`. Якщо порт `8788` теж зайнятий, актуальний інсталятор без `--port` автоматично знайде інший у зазначеному діапазоні.

Якщо попередній блок зупинився на `reset-failed` з повідомленням `Unit faborn-resolver.service not loaded`, PORT уже міг змінитися, а запуск ще не відбувся. `reset-failed` не потрібний для відновлення. Відновіть unit-файл з установленого пакета командою `install`, виконайте `daemon-reload`, `enable` та `restart`, як у виправленому блоці вище. Для перевірки використайте поточний PORT з `/etc/faborn-resolver.env`; повторно завантажувати Node не потрібно, якщо файли встановлення на місці.

Сервер уже вміє перевіряти непорожній `FABORN_ACCESS_KEYS` (кілька значень через кому) через Bearer-заголовок. **У цій першій бета залиште поле порожнім**: керування доступом та введення ключа в інтерфейсі Faborn будуть окремим наступним етапом після перевірки потоку. Ключі не повинні потрапляти у публічний JS або URL.

Зупинити й прибрати автозапуск без видалення файлів:

```sh
sudo systemctl disable --now faborn-resolver
```

Для локальної перевірки розробником, без інсталятора: Node.js 18+ і `node server/uakinogo/server.js`. Типово слухає тільки `127.0.0.1:8787`; `HOST=0.0.0.0` вмикає доступ із мережі. API: `GET /health`, `POST /v1/resolve` з JSON `{movie, season, episode, fresh}`. Немає довільного параметра URL, проксі відео або виконання скриптів сайту. Запити обмежені за часом, розміром, частотою та паралельністю.
